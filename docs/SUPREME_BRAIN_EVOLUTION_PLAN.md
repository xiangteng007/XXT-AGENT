## 🛠️ 2. 六大領域自我進步與打標機制 (Multi-Domain Feedback Rewards)

為了讓大腦在沒有人工干預的情況下「自我知道對錯」，我們為六大核心領域設計了**專屬的自動回饋（打標）邏輯**：

### 2.1 📈 領域一：智能投資與資產大腦
*   **決策快照**: 大腦產出股票/資產的 `BUY / SELL` 行動、目標價與止損點。
*   **自動打標 (T+7 天)**:  
    *   **Chosen**: 買入決策後，實際股價在 7 天內未跌破止損，且最大漲幅 $\ge +3.0\%$。
    *   **Rejected**: 買入決策後，股價跌破止損，或大腦判斷方向與市場真實走勢相反。

### 2.2 🏗️ 領域二：營建與結構工程 (Construction)
*   **決策快照**: 大腦針對某項工地建案，產出「物料估算表（水泥/鋼筋用量）」與「單價分析」。
*   **自動打標 (採購完成時)**:  
    *   **Chosen**: 實際工程採購單（由 QNAP NAS PostgreSQL 讀入）的物料數量與金額，與大腦估算變異率在 $\pm 5\%$ 以內。
    *   **Rejected**: 實際採購嚴重超支（變異率 $> +10\%$）或數量嚴重短估，代表大腦估算邏輯有結構性盲點。

### 2.3 ⚖️ 領域三：營建法規與合約合規 (Legal Compliance)
*   **決策快照**: 大腦審查協力商合約草稿，或生成 CNS 國家標準合規的施工安衛計畫書。
*   **自動打標**:  
    *   **Chosen**: 大腦產出的安衛計畫書，在送交外部審查或法務時「一次通過，無需任何文字修改」。
    *   **Rejected**: 法務或外部監造退件，並手動修改了合約條款或安衛項目。系統會將「法務手動修改後的最終版本」作為 Chosen，大腦原始輸出作為 Rejected 進行學習。

### 2.4 💾 領域四：NAS 基礎設施運維與故障自癒 (IT Ops)
*   **決策快照**: 大腦監控 QNAP NAS 系統狀態（Docker Uptime, Qdrant/ChromaDB 連線率），發現異常時自動建議並執行「特定容器重啟」或「磁碟清理腳本」。
*   **自動打標**:  
    *   **Chosen**: 執行大腦自癒建議後，系統在接下來的 24 小時內連線率保持 100%，CPU/記憶體負載回歸正常。
    *   **Rejected**: 執行自癒後服務依舊崩潰，代表自癒建議為無效噪音。

### 2.5 🤝 領域五：商業運營與 Partners CRM 同步
*   **決策快照**: 大腦根據 Partners CRM 中的客戶/廠商互動歷史，生成精確的「跟進電子郵件」或「工程進度匯報」。
*   **自動打標**:  
    *   **Chosen**: 發送跟進信後，客戶在 48 小時內回信並給出正面反饋。
    *   **Rejected**: 客戶未讀未回，或大腦漏掉了 CRM 中該客戶前一次提出的關鍵抱怨。

### 2.6 🚗 領域六：個人生活與車輛管家 (Butler)
*   **決策快照**: 大腦自動生成每日行程規劃、車輛定保保養提醒、或天氣豪雨警報的預警日程建議。
*   **自動打標**:  
    *   **Chosen**: 用戶（您）直接接受大腦產生的行事曆，無任何手動修改。
    *   **Rejected**: 用戶手動拖拽、修改或刪除了大腦生成的行程，系統自動將「用戶手動修改後的行程」記錄為最優偏好。

## ⚙️ 3. 混合領域聯合 LoRA 訓練與防遺忘機制 (Joint Task Tuning)

若大腦只進行營建法規的 DPO，它會忘記如何分析股票。為了解決這個問題，我們的 **Train Daemon (訓練守護進程)** 採取以下策略：

1.  **偏好緩衝池 (Preference Pool)**:  
    我們在 Redis / PostgreSQL 中建立一個「混合領域偏好池」。不論是財經、工程還是法規，生成的 DPO 數據對通通打上領域標籤：`{"domain": "legal", "chosen": "...", "rejected": "..."}`。
2.  **多任務混合採樣 (Multi-task Mixing)**:  
    當觸發 RTX 4080 SUPER 離線微調時，系統自動從資料庫抽取包含 **30% 財經 + 30% 工程 + 20% 法規 + 20% 運維與管家** 的黃金比例樣本混合在一起。
3.  **VRAM 資源協調鎖 (GPU Resource Lock)**:  
    在微調期間，為防顯示卡記憶體 (VRAM) 爆炸，系統會執行以下指令：
    ```bash
    # 卸載即時 Ollama 推理模型
    curl -X POST http://localhost:11434/api/generate -d '{"model": "qwen2.5-ST-brain", "keep_alive": 0}'
    
    # 執行 Python 聯合 LoRA 微調
    python src/training/supreme_joint_finetune.py --data_path=st_preferences.json
    
    # 合併權重並重新熱重載模型
    curl -X POST http://localhost:11434/api/generate -d '{"model": "qwen2.5-ST-brain"}'
    ```
